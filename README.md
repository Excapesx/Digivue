# digivue（仓库名 digipick）

数码与 AI 的社区站，上线在 digivue.top。

一句话定位：**数码看参数，AI 看信源。** 站点分成四个平行的板块——
工具箱、选数码、AI资讯、榜单，各做一件事，标准是同一条：说得清楚。

**零依赖、无外部请求**：不引 CDN、不引字体、不引框架，双击 `index.html` 就能跑。

```
digipick/
├── index.html          首页的唯一来源（构建时注入 SEO 信息）
├── style.css           全部样式（单文件，含响应式与动效）
├── data.js             参数库 + 价格层 + 路径规则（要改数据只动这个文件）
├── app.js              交互：预算控制台、产品板、对比、全站搜索
├── build.mjs           生成 dist/：首页 + 每款一个静态页 + 工具箱/榜单/AI资讯 + sitemap
├── refresh-price.mjs   刷新价格 → prices.json（现在是快照模式）
├── prices.json         价格表，由脚本生成，不要手改
├── daily.bat           Windows 任务计划用的每日「刷新 + 构建」
├── favicon.svg         站点图标
└── 构建与部署.md        构建、预览、部署、搜索收录的完整说明
```

## 主导航

首页 | 工具箱 | 选数码 | AI资讯 | 榜单，加上一个全站搜索（按 `/` 或点导航里的「搜索」）。

- **首页**：首屏左边是一句话，右边是四个板块的目录（款数由 data.js 实时填）；
  往下依次是「选数码」产品板（带预算滑杆）、推荐规则、对比演示、常见问题、完整产品索引。
- **选数码**：四个板块之一，首页产品板的锚点（`/#board`），任何页面都能一步跳过去。
- **工具箱**：预算选机、型号对比、预算榜单、全站搜索四件事，状态和入口都在一张表里。
- **榜单**：每个品类按预算档位列出价格最贴近的 3 款，超出预算的标出超出金额。
- **AI资讯**：筹备中的频道，先把「写什么、怎么写」公示出来。

## 一、现在怎么运行

直接双击 `index.html`。

如果浏览器因为本地文件限制不肯加载 `data.js`，在目录里起一个静态服务：

```bash
# 任选一种
python -m http.server 8080
npx serve .
```

然后访问 `http://localhost:8080`。

> ⚠️ 现在显示的是**演示样例数据**。参数和价格都不是厂商官方数据，也不是实时报价，
> 只用来验证功能。这一点在页面底部也写明了——替换数据前别对外发布。

## 二、已经实现的功能

- **预算滑杆 + 预设**：¥200–15000，首屏和产品板各一个、共用同一份状态；超过预算的型号自动隐藏并在计数里提示
- **「和预算的距离」**：每条产品带都会说清楚还剩多少余量，卡住预算的用强调色标出
- **参数搜索**：型号、品牌、卖点都能搜（搜「一加」或「M4」都能中）
- **四个品类**：手机 / 笔记本 / 平板 / 配件，左侧品类栏可切换
- **四种排序**：最合适 / 价格升降 / 预算余量
- **推荐理由**：每款产品有 `forWho` 字段，直接说「适合谁」——这比参数堆砌有用得多
- **对比**：勾 2–3 款，逐项对照，差异行高亮；跨品类会标「不适用」
- **可分享的链接**：预算、品类、排序、搜索词都写进 URL（`/?budget=5000&cat=phone#board`）
- **全站搜索**：导航里的动作，任何页面按 `/` 就能打开

### 一个刻意的设计：佣金不参与排序

`app.js` 里所有排序函数都不读 `commissionRate`。这不是疏漏，是本站的立身之本：
**推荐只看参数和预算是否匹配。** 以后改代码时请守住这条。

## 三、接真实价格（京东联盟 / 淘宝客）

价格分两层，各管一件事：

| 层 | 谁在跑 | 频率 | 结果写到哪里 |
|---|---|---|---|
| 第一层 | `node refresh-price.mjs` | 每天一次（`daily.bat` + 任务计划） | `prices.json` → 构建进静态 HTML |
| 第二层（可选） | `edge-api/price.js` 边缘函数 | 用户打开产品页时按需 | 页面上的当前价，KV 缓存 15 分钟 |

**价格跟着渠道的货走，不跟着型号走**：同一款手机在京东、淘宝是不同的 SKU。
所以 `data.js` 里的产品是「型号」，渠道挂 `offers`：

```js
{
  id: 'phone-redmi-k80', category: 'phone', brand: 'Redmi', name: 'Redmi K80',
  price: 2499,                    // 参考价：没接渠道时用它
  offers: [                       // 接了渠道后，价格从这里来
    { platform: 'jd', sku: '100012345678', pid: '你的推广位' },
  ],
}
```

多平台时取**最低价**当展示价，全部 offer 一起写进 `prices.json`；
构建时还会生成 `dist/offers.json`（只有平台和 SKU，不含任何密钥），给边缘函数用。

### 一、你要做的（第 1 步：接京东联盟）

1. **注册京东联盟**：union.jd.com，个人实名即可、免店铺；在后台创建一个**推广位**，
   拿到 **AppKey / AppSecret / 推广位 ID(PID)** 三样东西。
2. **填 `.env`（最简单的办法，新手看 [接京东联盟-新手步骤.md](接京东联盟-新手步骤.md)）**：
   用记事本打开 `D:\DSH\digipick\.env`，把三行等号后面填上，保存即可：

   ```ini
   JD_UNION_KEY=你的AppKey
   JD_UNION_SECRET=你的AppSecret
   JD_UNION_PID=你的推广位ID
   ```

   脚本每次运行会自动读它，不用重启。`refresh-price.mjs` 和 `discover.mjs` 都支持。
   也可以用环境变量（临时：`$env:JD_UNION_KEY="…"`；永久：`setx JD_UNION_KEY "…"` 后重开终端）。
3. **给产品补 SKU**：京东商品页地址是 `item.jd.com/100012345678.html`，
   那串数字就是 SKU；填进对应产品的 `offers` 里（可以先用联盟后台「推广商品」搜索核对型号）。
4. **先干跑一次**，不写文件：

   ```bash
   node refresh-price.mjs --provider jd --dry-run
   ```

   第一次大概率要在 `JD_PROVIDER` 里核对字段名（京东返回结构以官方文档为准，
   对不上时脚本会把原始返回打出来）。
5. 通过后去掉 `--dry-run` 正式写表 → `node build.mjs` 重新构建 → 上传 `dist/`。
6. 每天自动跑：`daily.bat` 已经串好「刷新 → 构建」，任务计划里指向它就行。

**验收标准**（三条都对上就算接通）：

- 刷新输出里有「有渠道价：N 款」，且不再提示「没有绑定 SKU」
- 产品页价格行变成「价格来自京东联盟，更新于 …」
- 页脚出现「（京东联盟）」+ 更新日期

### 二、想先验证管线？用模拟供应商

```bash
node refresh-price.mjs --provider mock --dry-run   # 只看会做什么
node refresh-price.mjs --provider mock             # 真的写一遍（会标注是模拟数据）
node refresh-price.mjs && node build.mjs           # 恢复参考价
```

它负责把你的 `offers` 按平台逐个造一条价格，用来验证「取价 → 校验 → 合并 → 渲染」整条链路，
不会联网，也不该拿去上线。

### 三、第二层（可选）：按需实时价

把 `edge-api/price.js` 部署成 EdgeOne 函数，配好同样的三个环境变量（有 KV 就再绑一个
`PRICE_CACHE`），然后把 `data.js` 里的 `PRICE_API` 改成 `'/api/price'`，重新构建上传。
取不到时页面会自动回退到静态参考价，不会空。

## 三之二、批量加型号（型号发现）

> 解决「产品太少」的第一步：先让机器把市面上的型号捞出来，再挑要收录的。

```bash
node discover.mjs --provider mock --pages 3 --fresh   # 模拟数据，验证清洗管线（不联网）
node discover.mjs --query "手机" --pages 2             # 京东联盟真接口（需 JD 环境变量）
node discover.mjs --query "微单" --category camera --pages 1
node discover.mjs --provider wikidata --limit 300 --fresh   # 只要名字时用这个：CC0，免备案、免密钥
```

它只做三件事：拿商品标题 → 清洗成「品牌 + 型号」→ 按型号聚合变体
（16GB/512GB、不同颜色是同一个型号的多个 SKU）。

输出两份：

| 文件 | 给谁用 |
|---|---|
| `data/candidates.json` | 机器用：型号候选 + 全部 SKU 变体 + 价格区间 + 是否已在库里 |
| `data/candidates.csv` | 人用：Excel 打开就能审核（品牌/型号/分类/变体数/价格/是否已有/原始标题） |

流程：跑脚本 → 打开 CSV 勾出要收录的型号 → 按清单补参数、绑 SKU、生成页面。
默认会合并历史结果，`--fresh` 重新起一份；当前 `data/candidates.*` 里是 mock 示例数据。

**只要型号名称、暂时不要参数** → 用 `--provider wikidata`。它按「智能手机 / 笔记本 / 平板 /
数码相机 / 智能手表 / 镜头 / 键鼠显示器 / 耳机」这些型号类拉数据，标签优先中文。
把 `--limit` 开到 8000 跑一次，原始结果是 **9,029 个不重复型号**；合并 Apple / 华为官网型号后，
候选池共有 **9,295 个型号**，其中 **330 个参数已核验**。CSV 里带 `sourceUrl`（维基数据条目），
按 CC0 使用，不要求署名。
（相机类目本身有 7,652 条、手机 2,189 条，已经基本拉满。）

### 已核验型号库（完整优先）

`build.mjs` 会读取 `data/candidates.json`，只发布参数可追溯的型号：

- `/models/`：已核验型号总览，按大类列出数量
- `/models/{大类}/`：按品牌分组的型号列表，每页 150 个，自动分页
- 参数已核验的型号直接链到产品页或官方参数页
- 只有名称、没有可靠参数来源的候选仍保存在 `data/`，但不生成页面、不进入搜索和 sitemap
- 全站搜索第一次打开时懒加载 `models.json`
- 入口：首页「选数码」下方、工具箱、页脚、移动端菜单

当前：公开库 **330 个已核验型号 · 10 个列表页**；另有 **8,965 个候选被隐藏**。型号库页面是纯列表（没有照片），
设计检测器的「图片下限」不适用；其余页面保持 0 FAIL。

### 品牌官网：官方参数页（Apple / 华为 / 小米 / 三星 / 佳能 / 尼康）

`brands.mjs` 从品牌官网 sitemap 找 `/specs/` 页面，抽取「小节 → 内容」：

```bash
node brands.mjs --limit 300          # Apple 26 + 华为 277 个 spec 页，约 6–8 分钟
node brands.mjs --limit 4 --dry-run  # 先试几个
node official-more.mjs               # 小米 sitemap 的 288 个 /specs/ 页
node official-samsung.mjs            # 三星手机家族 + 官方规格接口
node official-canon.mjs              # 佳能相机规格表
node official-nikon.mjs              # 尼康相机 / 镜头技术规格
node build.mjs                       # 生成 /specs/ 参数页并链进型号库
```

- 抽取方式：Apple 用 `.techspecs-row`，华为用 `.large-accordion__button`
- 每条参数页都保留 **sourceUrl** 指向官方页面，并写明抓取日期
- 已有完整参数的产品（43 款）中，能和候选池型号对上的条目链到产品页；其余官方型号标「官方参数」
- 当前：**322 个官方参数页**（苹果 25、华为 249、小米 18、三星 8、佳能 12、尼康 10）；
  与 10 个原产品页匹配项合并去重后，公开库共有 **330 个已核验型号**
- 页面在 `/specs/{品牌-型号}/`，已加入 sitemap 与全站搜索
- 26 个 Apple 页面里 iMac 等少数老结构没抽到；华为 277 个里 22 个老页面跳过，
  不影响其余页面。价格与购买链接仍待接入联盟 API。

## 四、接价格时必须守的规矩

这些不是法律条款，是**联盟协议**——违反了平台可以直接停你的 AppKey，比打官司快：

1. **价格要实时拉取，不要长期缓存。** 协议通常限制数据缓存时长。本站的
   `priceCache` 只在一次页面会话内生效，不落库、不写 localStorage——**请保持这样**
2. **商品图和标题只能用于推广该商品**，不能挪用
3. **必须带推广链接**（你的 pid）
4. **别把 API 数据转卖给第三方**——最常见的封号原因
5. 个人号有 QPS 和日配额，所以价格要按需查、不要预刷全量

这些约束不会让站点变慢或变难用。它们和「静态参数库 + 动态价格层」的架构天然契合。

## 五、加一款产品

只改 `data.js`，在 `PRODUCTS` 数组里加一项：

```js
{
  id: 'phone-example',              // 唯一，别重复
  category: 'phone',                // 必须是 CATEGORIES 里的 id
  sub: 'watch',                     // 大类有 subs 时必填（wearable → watch）；大类没有细分就不写
  brand: '品牌',
  name: '型号全称',
  price: 2999,                      // 数字，不带引号不带 ¥
  commissionRate: 0.02,             // 0.02 = 2%；0 表示没有推广链接
  specs: {                          // 键必须和 SPEC_FIELDS.phone 对得上
    soc: '...', ram: '...', storage: '...', screen: '...',
    battery: '...', charge: '...', camera: '...', weight: '...',
  },
  tags: ['一句话卖点', '另一个卖点'],
  forWho: '一句话说清这款适合谁',
}
```

**不用改前端。** `data.js` 末尾有一段自检代码，启动时会在控制台报出：
id 重复、品类不存在、参数缺字段、参数名拼错。加完产品打开控制台看一眼就行。

## 六、已知的取舍与后续可做的事

**现在的实现**

- 每次输入都整块重建产品板。20 多款产品毫无问题，几百款以上建议改成只更新变化的行
- 没有分页/虚拟滚动，同上
- SEO 已解决：`build.mjs` 给每款产品生成独立静态页，参数是纯 HTML
- 产品页没有实物照片（演示数据阶段刻意不做，避免拿别人的商品图当自己的）

**上线前要补的**

- [ ] 替换成厂商官方参数，核对准确性
- [ ] **ICP 备案**（大陆节点必须，免费但需 1–20 个工作日；见下方「备案」）
- [ ] 备案后 30 日内做公安备案
- [ ] 部署到 EdgeOne Pages（免费版不限流量），接上边缘函数
- [ ] 加隐私政策页（备案和联盟申请都可能要）

### 备案（当前未办）

- **要不要办**：用 EdgeOne 的**中国大陆节点/大陆加速**就必须 ICP 备案；只用**海外节点**则不需要（但国内访问更慢）。当前部署在哪个可用区，看 EdgeOne 控制台的部署设置。
- **个人还是企业**：个人备案不允许经营性内容。本站计划挂联盟推广链接、拿佣金，这在口径上偏商业化，**建议用个体工商户/企业备案**；先用个人备案的话，推广链接要谨慎。
- **流程**：域名先实名（注册人=备案主体，注册商需为国内持牌）→ 腾讯云备案控制台提交（主体+网站信息、证件、核验）→ 腾讯云初审 → 管局审核（1–20 工作日）→ 短信核验 → 拿备案号。
  如果 EdgeOne Pages 没有可用的「备案服务码」，需要一台最便宜的腾讯云轻量/CVM 或问客服接入方式。
- **首次备案期间**：按腾讯云提示关闭网站/暂停域名解析，通过后再上线。
- **公安备案**：ICP 通过后 30 日内到 `beian.mps.gov.cn` 提交，拿公安备案号。
- **页脚展示**：拿到号后填 `build.mjs` 里的 `SITE.icp` / `SITE.police`，重新构建，页脚会自动出现带链接的备案号（已留好钩子，留空不输出）。

## 六之二、设计说明（改样式前先看这段）

- **方向**：印刷型录。首页当成一本型录来做——封面大字、品牌带、整块橙色目录带、内页数据。
  空间不够就放大字号，不加装饰（这条来自 distinctive-ai-design 的「减法精修」）。
- **首屏三件套**：全宽大字报头（`--t-display`，最高 104px）→ 品牌带（慢速滚动，悬停暂停、
  减少动效时静止换行）→ 橙色目录带（四个板块，全页唯一的大面积颜料动作）。
- **产品自己会工作**：选数码那块的真控件（预算滑杆）在产品板工具栏里，拖一下读数和列表一起变。
- **电子层**（借 React Bits 的组件思路，全部用平色 + 原生 Canvas 重做，没有渐变/发光/玻璃）：
  - 首屏波场（`Dot Grid` + 水面波纹）：Canvas 点阵铺在大字下面，两层速度不同的斜向行波持续推过整片；
    鼠标顶起附近一片点并染成强调色，扫过会留下扩散的涟漪（最多 5 圈，1.8 秒散完）。
    首屏离开视口或标签页切到后台就停；系统开减少动效时只画一帧静止点阵
  - 绕边信号（`Star Border`）：主按钮边上有一颗 6px 方块按 `offset-path` 跑一圈（6 秒）
  - 指示灯（`LED`）：品牌带的品牌逐颗亮起，错开 0.42 秒；无缝循环的复制段不重复动画
  - 电流轨迹（`Glare Hover`）：目录行 hover / 键盘聚焦时，一道 3px 轨道从左划过
  - 点击火花（`Click Spark`）：点击按钮/分类/目录行时溅出 6 个方形小点，落在橙色带上自动换成深色
  - 数字解密（`Decrypted Text`）：目录带的规模数字先乱跳再落位
- **调色**：石墨底 `#18191b` + 一个强调色 `#ff4a1f`；中间一整段浅色底 `#eff0f1` 把页面分成两半。
- **字体**：只用系统字体（`Segoe UI` / `PingFang SC` / `Microsoft YaHei`），不引外部字体——
  大陆访问 Google Fonts 会失败，站点也一直是零外部请求。
- **字号只有六级**：14 / 16 / 20 / 36 / 43 / 104（桌面）。首屏大字和页脚字标用 `--t-display`，
  目录带用 `--t-big`，子页与产品页标题也用 `--t-big`（不继承 104px，否则长型号会折成三行）。
- **方角**：页面级元素一律方角，只有 `data-ui` 标记的产品片段内部保留小圆角。
- **自检**：`node lint.mjs`（taste-skill）静态扫源码，`node inspect.mjs` 用真实浏览器量渲染。
  两者都应该 0 FAIL；改完样式跑一遍，比肉眼靠谱。

# 协作方式（两个人开发）

> 本节为仓库建立时的原始约定，保持不变。

## 分支策略：**直接在 main 上开发**（本项目约定）

```bash
# 每天开工前
git pull

# 干完活
git add .
git commit -m "feat: 说明改了什么"
git push
```

**⚠️ 虽然不做强制，但仍建议**：
- 改动大或要试错时，**开个分支**（`git checkout -b feature/xxx`），试通了再合回 main
- **推之前先 `git pull`** —— 不然可能被拒（别人推过东西了）

## 遇到 `push` 被拒（non-fast-forward）

```bash
git pull --rebase        # 把你的提交放到对方提交之后
git push
```

## 提交信息（commit message）

```
feat:  新功能
fix:   修 bug
docs:  文档
build: 构建/依赖相关
perf:  性能优化
refactor: 重构（不改行为）
chore: 杂项
```

例：`fix: 修复配置文件解析在空行处崩溃`

## 约定（建议）

- **不要提交**：编译产物、密钥/证书、日志、`.env` —— `.gitignore` 已经挡了大部分 ✓
- **配置文件**：提交 `xxx.conf.example`，真实配置放本地（`.gitignore` 里已忽略 `*.conf.local`）
- **大文件**：>10 MB 的文件别直接提交（Git 历史里删不干净）

### 本项目的密钥怎么放

价格层需要京东联盟的三个值。在项目根目录建 `.env`（**已被 git 忽略，不要提交**）：

```ini
JD_UNION_KEY=你的AppKey
JD_UNION_SECRET=你的AppSecret
JD_UNION_PID=你的推广位ID
```

`env.mjs` 会读取它；已存在的系统环境变量优先，不会被覆盖。
边缘函数用平台的环境变量面板配置，不要写进代码。
